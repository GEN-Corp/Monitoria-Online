AMBIENTE LOCAL

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
Copy-Item .env.example .env
# Preencha FIREBASE_PROJECT_ID, FIREBASE_API_KEY e as credenciais Firebase no .env
python manage.py seed_demo --project-id SEU_ID_DO_PROJETO_FIREBASE
python manage.py runserver

O comando seed_demo solicita uma senha no terminal e a define para todas as
contas de demonstração no Firebase Authentication. A senha não aparece na tela
e não fica salva no Git. O comando verifica o ID do projeto explicitamente.

CRIAR PROFESSOR OU MONITOR REAL

Crie as contas com create_firebase_user. O comando solicita a senha duas vezes,
sem exibi-la ou gravá-la:

python manage.py create_firebase_user --project-id SEU_ID_DO_PROJETO_FIREBASE --email professor@exemplo.com --username professor --first-name Professor --role PROFESSOR
python manage.py create_firebase_user --project-id SEU_ID_DO_PROJETO_FIREBASE --email monitor@exemplo.com --username monitor --first-name Monitor --role MONITOR

Depois, o professor entra no sistema, cria a disciplina e associa o monitor.

CONFIGURAR FIREBASE PARA DESENVOLVIMENTO

1. No Firebase Console, crie/abra o projeto e habilite Authentication > E-mail/senha.
2. Crie um banco Cloud Firestore em modo de produção.
3. Em Configurações do projeto > Geral, copie o ID do projeto e a chave Web API.
4. Em Configurações do projeto > Contas de serviço, gere uma chave privada do
   Firebase Admin SDK. Guarde o JSON fora da pasta do repositório.
5. Copie .env.example para .env e preencha FIREBASE_PROJECT_ID e FIREBASE_API_KEY.
   Para FIREBASE_SERVICE_ACCOUNT_BASE64, converta o arquivo JSON da conta de
   serviço para Base64 sem imprimir a chave no terminal:

   $serviceAccountPath = Read-Host "Caminho do JSON da conta de serviço"
   [Convert]::ToBase64String([IO.File]::ReadAllBytes($serviceAccountPath)) | Set-Clipboard
   # Cole o conteúdo da área de transferência no valor local de .env.
   Crie também DJANGO_SECRET_KEY:
   python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"

   Para usar os emuladores, preencha também FIRESTORE_EMULATOR_HOST e
   FIREBASE_AUTH_EMULATOR_HOST com 127.0.0.1:8080 e 127.0.0.1:9099.
6. Para emuladores, instale o Firebase CLI e execute:
   firebase emulators:start --only auth,firestore --project SEU_ID_DO_PROJETO_FIREBASE
7. Publique as regras e índices do repositório:
   firebase deploy --only firestore:rules,firestore:indexes --project SEU_ID_DO_PROJETO_FIREBASE

PUBLICAR NA VERCEL

1. Importe a branch SCRUM-55 no projeto Vercel ou selecione-a no projeto já criado.
   Configure Root Directory como a raiz do repositório e Framework Preset como
   Django (detecção automática também deve encontrar manage.py). O arquivo
   .python-version fixa Python 3.12 e vercel.json configura a função Django/WSGI.
2. Antes de fazer o deploy, abra Settings > Environment Variables e adicione:

   FIREBASE_PROJECT_ID                 ID do projeto Firebase
   FIREBASE_API_KEY                    Chave Web API do app Firebase
   FIREBASE_SERVICE_ACCOUNT_BASE64     JSON da conta de serviço em Base64
   DJANGO_SECRET_KEY                   Chave aleatória Django
   DJANGO_DEBUG                        false
   DJANGO_ALLOWED_HOSTS                .vercel.app
   DJANGO_CSRF_TRUSTED_ORIGINS         https://*.vercel.app

   Adicione as variáveis a Production, Preview e Development. Se usar domínio
   próprio, inclua também o domínio em DJANGO_ALLOWED_HOSTS e sua origem HTTPS
   em DJANGO_CSRF_TRUSTED_ORIGINS. Salve e faça redeploy para aplicar alterações
   nas variáveis. Na Vercel, DEBUG é desativado automaticamente e os domínios
   atuais de Preview/produção são reconhecidos pelas variáveis da plataforma.
3. Gere uma chave Django localmente e cadastre-a diretamente na Vercel:

   python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"

   Não a salve neste repositório.
4. No Firebase Console > Authentication > Settings > Authorized domains,
   adicione o domínio Vercel de produção e o domínio de Preview que será usado.
5. Faça deploy pela Vercel. O Git push na branch conectada inicia um deploy de
   Preview; após testar, faça merge para a branch Production configurada.

O build nativo da Vercel coleta os arquivos estáticos do Django. Firebase Admin
usa a conta de serviço do servidor; regras Firestore não autorizam acesso direto
dos navegadores. Nunca cole credenciais no chat, commit ou issue.
