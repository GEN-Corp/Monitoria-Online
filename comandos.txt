# Preencha FIREBASE_PROJECT_ID, FIREBASE_API_KEY e as credenciais Firebase no .env
python manage.py seed_demo --project-id SEU_ID_DO_PROJETO_FIREBASE
python manage.py runserver

O comando seed_demo solicita uma senha no terminal e a define para todas as
contas de demonstração no Firebase Authentication. A senha não aparece na tela
e não fica salva no Git. O comando verifica o ID do projeto explicitamente.

CRIAR PROFESSOR OU MONITOR REAL

Crie as contas com create_firebase_user. O comando solicita a senha duas vezes,
sem exibi-la ou gravá-la:

python manage.py create_firebase_user --project-id SEU_ID_DO_PROJETO_FIREBASE --email professor@exemplo.com --username professor --first-name Professor --role PROFESSOR
python manage.py create_firebase_user --project-id SEU_ID_DO_PROJETO_FIREBASE --email monitor@exemplo.com --username monitor --first-name Monitor --role MONITOR

Depois, o professor entra no sistema, cria a disciplina e associa o monitor.

CONFIGURAR FIREBASE PARA DESENVOLVIMENTO

1. No Firebase Console, crie/abra o projeto e habilite Authentication > E-mail/senha.
2. Crie um banco Cloud Firestore em modo de produção.
3. Em Configurações do projeto > Geral, copie o ID do projeto e a chave Web API.
4. Copie .env.example para .env e preencha FIREBASE_PROJECT_ID e FIREBASE_API_KEY.
   Para usar os emuladores, preencha também FIRESTORE_EMULATOR_HOST e
   FIREBASE_AUTH_EMULATOR_HOST com 127.0.0.1:8080 e 127.0.0.1:9099.
5. Para emuladores, instale o Firebase CLI e execute:
   firebase emulators:start --only auth,firestore --project SEU_ID_DO_PROJETO_FIREBASE
6. Para acessar o Firestore real localmente, configure
   GOOGLE_APPLICATION_CREDENTIALS com o caminho de uma chave de conta de serviço.
   Nunca adicione essa chave ao Git.
7. Publique as regras e índices do repositório:
   firebase deploy --only firestore:rules,firestore:indexes --project SEU_ID_DO_PROJETO_FIREBASE

PUBLICAR O SERVIDOR

O Firestore guarda os dados compartilhados. O Django precisa também de um
servidor HTTPS, por exemplo Google Cloud Run; Firebase Hosting sozinho não
executa o backend Django.

No Google Cloud:
1. Habilite Cloud Run, Cloud Build e Firestore.
2. Use uma conta de serviço do Cloud Run com acesso ao Firestore e Firebase Authentication.
3. Publique o projeto com Cloud Run a partir do repositório.
4. Configure FIREBASE_PROJECT_ID, FIREBASE_API_KEY, DJANGO_DEBUG=false,
   DJANGO_ALLOWED_HOSTS com o domínio run.app atribuído ao serviço,
   DJANGO_CSRF_TRUSTED_ORIGINS com a origem HTTPS pública e DJANGO_SECRET_KEY.
   Guarde DJANGO_SECRET_KEY no Secret Manager, não neste arquivo.

Para gerar uma chave secreta localmente (cadastre o resultado diretamente nas
variáveis protegidas do provedor, sem salvar o resultado no Git):
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"

Comandos de publicação:
python -m pip install -r requirements.txt
python manage.py collectstatic --noinput

O Procfile inicia o servidor Gunicorn. As páginas de conversa consultam o
servidor a cada cinco segundos para exibir novas respostas sem atualizar a tela.
Nunca publique senhas, chaves privadas ou arquivos de conta de serviço.
